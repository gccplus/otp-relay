# Mac 客户端

## 开发构建

需要 Swift 6 工具链（Xcode 16 或更新版本），运行环境为 macOS 13 或更新版本：

```bash
swift test
swift run OTPRelayMacApp
```

应用以菜单栏形态运行，默认自动复制新验证码，可在设置中关闭。验证码按短信接收时间最新优先展示，
默认展开最新一条、显示最近三条，其余记录可展开或收起。已展示的验证码加密保存在
本机钥匙串中并在 24 小时后删除；系统通知固定显示“收到一条验证码”。
通知在应用位于前台时也会显示横幅，不包含验证码、来源或短信正文。可在设置页查看
授权状态并发送测试通知；系统拒绝授权时可直接跳转到 macOS 通知设置。

左键菜单栏图标只打开验证码面板；右键菜单栏图标提供原生菜单，可选择“退出”、
“打开验证码面板”和“偏好设置”。
扫码配对、通知、服务器和解除配对位于独立设置窗口。解除配对会同步撤销云端凭证，
并清除本机配对信息和验证码记录。退出应用会保留配对信息。

未配对时可在设置页配置云端域名，只填写类似 `otp.example.com` 的域名，不填写协议、
端口或路径。客户端会固定使用 `https://<域名>/otp-relay`；已配对时显示该配对
实际使用的域名，如需切换服务器需先解除配对。

`Info.plist` 已包含菜单栏应用所需的 `LSUIElement`。正式 DMG 仍需在完整 Xcode 环境中生成 App Bundle，使用 Apple Developer ID 签名，并提交公证。

本地联调不要直接使用默认 ad-hoc 签名打包，因为其指定身份会随二进制哈希变化，
导致新版无法访问旧版创建的钥匙串条目。统一使用：

```bash
./scripts/package-local.sh
```

脚本会为本地调试包写入稳定的 `com.otprelay.mac` 指定身份。正式发布时通过
`OTP_RELAY_SIGNING_IDENTITY` 指定 Developer ID Application 证书，不能继续使用
本地调试签名。本地调试签名没有数据保护钥匙串权限，客户端会自动回退到普通
macOS Keychain。安装版和未打包的 SwiftPM 调试进程使用不同的钥匙串命名空间，
避免临时签名变化造成旧密钥无法覆盖；正式签名并配置相应 entitlement 后可继续
使用数据保护钥匙串。

如需生成仅供本机安装的 DMG：

```bash
./scripts/build-local-dmg.sh
```

生成物位于 `dist/`，打开后将“验证码同步”拖入 Applications。该 DMG 没有经过
Apple 公证，只能用于本地联调，不应对外分发。
